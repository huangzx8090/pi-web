# v0.9.2-titles — 会话标题更短、可生成、模型可配置

本次更新集中解决「会话标题太长」这件事，并顺带修掉了一个让自动命名**一直静默失败**的隐蔽问题。

> ⚠️ 个人 fork，非官方项目。上游：[agegr/pi-web](https://github.com/agegr/pi-web)。

## 🔍 先说根因：自动命名其实一直在失败

排查时发现，用默认模型（`workbuddy-cn/cn:glm-5.3` 这类**强制思考**的模型）时，标题请求的 token 上限只有 **256**，而模型会先用掉几百个 token 思考，整段预算被思考块吃光（`stopReason=length`），**根本没有输出文本块** → 接口报「没有返回标题」→ 自动命名静默失败。

于是侧边栏里显示的其实是**首条消息硬切 50 字符**的兜底文案，又长又会换行。这就是「标题太长」的直接原因。

实测（同一段对话，同一模型）：

| maxTokens | stopReason | 输出 | 结果 |
| --- | --- | --- | --- |
| 256（旧） | length | 256 | ❌ 只有思考，无标题 |
| 512 | stop | 335 | ✅ `修复标题过长及模型配置` |
| 1024（新） | stop | 565 | ✅ `修复标题过长并支持模型配置` |

## ✨ 更新内容

### 1. 标题长度收敛到侧边栏能显示的范围
- 生成侧上限从「80 字符」改为按语种计：**中文 16 字 / 拉丁 32 字符**，提示词同步收紧为「约 8-14 个中文字，或 3-6 个词；单一短语，不要副标题、不要冒号拼接、不要尾标点」。
- 截断优先在标点/空格处断开，避免出现「半个词」；只有断点保留了大半预算时才采用。
- 未命名会话的兜底标题不再硬切 50 字符，改用同一套截断规则，**保证一行放得下**。

### 2. 生成标题用哪个模型，可以自己配
- 设置 → 常规 里新增「**标题模型**」，留空 = 跟随会话模型。
- 配置写在 pi-web 自己的设置文件 `~/.pi/agent/pi-web/settings.json`（`titleProvider` / `titleModel`），不碰 pi 的 `settings.json`，两者不会互相覆盖；写入带文件锁、保持未知字段、权限 `0600`。
- 取值在会话的模型运行时里解析，复用会话已有的凭据；**配置的模型不存在或读设置失败时自动回退到会话模型**，不会让命名直接报错。

### 3. 生成时机改到「首轮回复落地之后」
- 旧行为：首条用户消息落盘后 600ms 就开始命名——此时还不知道这轮到底做成了什么，标题只能猜意图，偏长偏泛。
- 新行为：等到**首轮回复产出且本轮跑完**（`assistantMessages > 0` 且会话不在运行中）再命名，转录里同时有「用户要什么」和「实际做成了什么」。只对新会话触发一次，浏览旧对话不消耗 token，手动改过名的不会被覆盖。

### 4. 出错信息能看懂了
- token 用尽导致没有标题时，报错会说明是预算问题（`ran out of tokens before answering`），而不是含糊的「模型没有返回标题」。

## 📦 数据

| 文件 | 内容 |
| --- | --- |
| `~/.pi/agent/pi-web/settings.json` | `titleProvider` + `titleModel`（标题模型；留空即跟随会话模型） |

## 🚀 使用

```bash
git clone https://github.com/huangzx8090/pi-web.git
cd pi-web
npm install
npm run dev
```

设置 → 常规 → 标题模型：想省钱就指一个便宜的小模型；留空则用当前会话的模型。

## ⚠️ 已知事项

- 本次未改动平台相关逻辑，macOS 之外的平台未做额外验证。
- 未命名会话的兜底标题仍然取首条消息的**开头**；如果第一句是铺垫（「帮我看看」），兜底标题可能不够准——等首轮回复后的自动命名会覆盖它。
